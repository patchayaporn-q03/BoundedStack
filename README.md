1. โจทย์ (Problem Statement)
โจทย์ของแลปนี้คือ:
จงออกแบบและพัฒนา ADT ชื่อ BoundedStack — สแตกที่เก็บข้อมูลได้สูงสุดตามความจุที่กําหนดตอนสร้าง —
ให้ผู้อื่นนําไปใช้ต่อได้จริงโดยไม่ต้องอ่านโค้ดภายใน และนิสิตต้องพิสูจน์ให้ได้ว่ามันถูกต้อง ด้วย test ที่รันได้ ไม่ใช่ด้วยคําพูด
นี่คือรายละเอียดทั้งหมดของโจทย์ ไม่มีการระบุ requirement รายข้อ ไม่มีรายการเมธอดที่ต้องมี ไม่มีตัวอย่าง input/output ให้
นิสิตต้องตัดสินใจเองทั้งหมดว่า:
• BoundedStack ควรทําอะไรได้บ้าง และอะไรที่ไม่ใช่หน้าที่ของมัน
• จะมี operation อะไรบ้าง ชื่ออะไร และแต่ละตัวมี spec อย่างไร (precondition / postcondition / กรณีผิดพลาด)
• จะเก็บ representation ด้วยโครงสร้างอะไร เพราะอะไรจึงเลือกแบบนั้น และจะซ่อนมันอย่างไร
• เมื่อสแตกเต็มแล้วมีการใส่ข้อมูลเพิ่ม ควรเกิดอะไรขึ้น — โยน exception, คืนค่าบอกผลสําเร็จ, หรือไม่ทําอะไร
ท่านเลือกทางไหนและเพราะอะไร
• เมื่อสแตกว่างแล้วมีการหยิบข้อมูลออก ควรใช้ assertion หรือ exception จัดการ และเหตุผลคืออะไร
• ความจุเท่ากับศูนย์ หรือความจุติดลบ ถือว่าถูกต้องหรือไม่ และจะจัดการอย่างไร
• จะทําให้ ADT เป็น mutable หรือ immutable และผลของการเลือกนั้นคืออะไร
• จะทดสอบอย่างไรให้เชื่อได้ว่ามันถูกต้อง และคําว่า “พอ” หมายถึงเท่าไร
• จะจัดลําดับการทํางานอย่างไร (เขียนโค้ดก่อน หรือเขียน test ก่อน)
อาจารย์จะไม่ตอบคําถามว่า “ต้องทําอะไรบ้าง” แต่จะตอบคําถามว่า “ทําไมสิ่งที่คิดไว้ถึงดีหรือไม่ดี”

2. ข้อจํากัด (Constraints)
ข้อจํากัดต่อไปนี้เป็นกรอบเดียวที่กําหนดให้ ส่วนที่เหลือเป็นอิสระของนิสิต
• C1 — ส่ง ADT เพียง 1 ตัวคือ BoundedStack และ client ต้องไม่สามารถเข้าถึงหรือแก้ไข representation
ได้โดยตรงไม่ว่าทางใด
• C2 — ต้องมี operation ครบทั้ง 4 บทบาท: Creator, Producer, Observer, Mutator อย่างน้อยบทบาทละ 1 ตัว
(ถ้าเลือกทํา immutable type แล้วไม่มีMutator ต้องอธิบายเหตุผลเชิงออกแบบให้ชัด)
• C3 — ต้องมี Abstraction Function และ Representation Invariant เขียนเป็น comment เหนือ private fields
และต้องมี checkRep() ที่เรียกจริง
• C4 — ต้องเขียน test runner เอง ห้ามใช้ JUnit / TestNG / assertJ หรือ framework ใด ๆ ผลลัพธ์ต้องพิมพ์ PASS/FAIL
และสรุปจํานวนรวมได้เอง
• C5 — ห้ามใช้ AI generate โค้ดหลักหรือ test ทั้งก้อน (ใช้ถามแนวคิดได้)
• C6 — โค้ดทั้งหมดต้องคอมไพล์และรันด้วย javac / java เปล่า ๆ ไม่มี build tool
• C7 — งานที่ส่งต้องมีหลักฐานลําดับการพัฒนา (commit log) ที่แสดงให้เห็นว่าท่านทํางานอย่างไร
• C8 — ขนาดงานที่คาดหวัง: ADT ประมาณ 80–150 บรรทัด และ test ประมาณ 20-40 – เคส — ถ้าเกินไปมาก
แปลว่าขอบเขตกว้างเกินความจําเป็น
• C9 — ห้ามใช้ java.util.Stack หรือ Deque เป็น representation ภายใน (จะกลายเป็นการห่อของที่มีอยู่แล้ว
ไม่ได้ออกแบบเอง) — ใช้ array หรือ ArrayList เป็นฐานได้
3. สิ่งที่ต้องส่ง (Deliverables)
นิสิตเป็นผู้ตัดสินใจว่าเนื้อหาในแต่ละชิ้นควรมีอะไร — ที่กําหนดคือ “ต้องมีชิ้นนี้” เท่านั้น

5. คําถามที่ท่านต้องตอบให้ตัวเองก่อนส่งงาน
ไม่ต้องส่งคําตอบเหล่านี้ แต่ถ้าตอบไม่ได้ แปลว่างานยังไม่เสร็จ
• ถ้าพรุ่งนี้ต้องเปลี่ยน representation จาก array เป็น ArrayList (หรือกลับกัน) client จะพังกี่บรรทัด?
• ถ้ามีคนแอบแก้โค้ดของท่านให้ผิดหนึ่งบรรทัด test ของท่านจะจับได้ไหม?
• test ตัวไหนที่ท่านเขียนขึ้นเพราะ “มันควรมี” มากกว่าเพราะ “มันเสี่ยงจริง”?
• ท่านทดสอบครบหรือยัง: ว่าง · มีตัวเดียว · เกือบเต็ม · เต็มพอดี · เต็มแล้วใส่เพิ่ม · ว่างแล้วหยิบออก · ความจุ 1 · ความจุ 0?
• ถ้ามีคนส่ง null / ค่าติดลบ / ค่าว่าง / ค่ามหาศาลเข้ามา จะเกิดอะไรขึ้น และท่านตั้งใจให้เกิดแบบนั้นหรือไม่?
• ถ้า client เอาค่าที่ได้จาก observer ไปแก้ สแตกของท่านจะเปลี่ยนตามไหม?
• ถ้าตัดชื่อฟังก์ชันออกหมดแล้วให้คนนอกอ่าน เขาจะเดาได้ไหมว่าแต่ละตัวทําอะไร?
